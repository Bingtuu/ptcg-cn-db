# 文档精简与归档设计（task 066）

日期：2026-10-25
状态：已获用户批准

## 背景与问题

- `STATUS.md` 约 147 KB，长篇任务总结、已关闭技术债和逐日日志持续堆叠。
- `AGENTS.md` 约 32 KB，其中大部分当前状态与 STATUS 重复，工程规则反而难以定位。
- `README.md` 约 25 KB，长度可接受，但测试数、PRD 链接、快速预览、合法卡池等存在过时内容；实时 DB 与 dist 快照的统计口径混在一起。
- 历史仍有追溯价值，不能简单删除；完整任务细节已部分存在于 `tasks/done/` 与 `reports/`，但逐日时间线需要一份集中快照。

## 目标

让新会话只读取当前工作所需内容，同时保留完整历史证据；修正 README 的事实与版本口径，不改变任何代码、数据模型或数据库内容。

## 非目标

- 不重写 PRD、任务档或历史报告。
- 不压缩 README 的统计教程与复算示例。
- 不继续 task 060 的实现；其 worktree 保留，文档整理完成后恢复。

## 方案

### 1. 单份完整历史快照

在编辑前将当前完整 `STATUS.md` 原样复制为：

`docs/archive/STATUS-2026-10-25.md`

该文件是只读历史快照，后续不随每日进展更新。`AGENTS.md` 删除的重复历史可由这份快照和 `tasks/done/` 追溯，不再制造第二份重复归档。

### 2. 精简 STATUS.md

保留以下结构：

1. 当前状态：卡牌实时数据、dist 版本、嗨皮组合 L0、task 059 结果、task 066 当前整理、task 060 暂停及 061–065 队列、10-25 赛事轮询异常。
2. 入口：权威文档、工程约定、任务队列、数据源、代码、数据与归档链接。
3. 里程碑：M0–M12 已完成状态压缩为短清单，不附历次数字与修复细节。
4. 当前有效决策：仍影响后续工作的口径，链接原任务/PRD；纯粹已完成的拍板不展开。
5. 当前运维与技术债：只列未关闭项及其承接任务；已关闭、已自愈、已有 DONE 任务的事项移出正文。
6. 近期记录：只留 2026-10-25 本轮工作摘要，更早逐日记录由归档承接。

正文不再追求记录每一次数字变化；动态数字必须带日期或 dist 版本。目标控制在当前工作可快速读完的范围，不设机械行数指标。

### 3. 精简 AGENTS.md

定位为工程手册，保留：

- 项目定位与权威文档链接；
- 一小段当前摘要及 task 060 暂停状态；
- 技术栈与结构约束；
- 全部硬性规矩；
- 常用命令；
- 任务工作循环。

删除与 STATUS 重复的历史任务总结。当前摘要只写后续工作必须知道的事实，详细进展链接 STATUS 与归档。

### 4. 修正 README.md

保留现有结构、统计教程和复算示例，修正：

- 开发自检测试数为 1190；
- 文档区 PRD 链接为 v1.38；
- 快速预览为 137 系列 / 13,057 active，并更新 2026-10-25 合法卡池；
- 卡牌实时数据与 dist v20261025.1 赛事快照分开标注；
- 亮点和 Roadmap 中容易造成“实时赛事总量”误解的数字改成带版本的快照口径，或链接 manifest；
- 当前快照、schema 2.0.0 仍属 task 060 工作目标，不提前写成已完成事实。

### 5. 任务与提交边界

建立 `tasks/066-文档精简与归档.md`，独立使用 `task(066):` 提交。task 060 在 STATUS 中标记暂停，task 066 完成后恢复；不改变 task 060 worktree 中的代码。

- 从 `reports/acceptance-20261025.md` 核对 A1–A8 与合法卡池。
- 检查 README、STATUS、AGENTS 中 PRD 版本、测试数和任务状态一致。
- 检查归档与精简前 STATUS 逐字节一致（归档复制后、正文重写前验证）。
- 检查内部相对链接和归档链接存在，运行 `git diff --check`。
- 仅文档变化，无需重复全量 pytest；最终说明验证范围，不把文档检查表述为代码测试。
