# 赛事身份统一设计（task 062）

日期：2026-10-25
状态：已获用户分节批准

## 背景与目标

mik 赛事 3710 两队共用 deck `mik_moe:688431` 且 `rank=-1`，现有 `(deck_id,tournament_id,rank)` 主键无法表达两次真实出战。EN 两通道直接哈希原始数组，条目重排或重复条目表示差异会制造重复 deck 实体；共享 deck 的映射环境还受 ingest 顺序影响。

目标是建立稳定的出战与内容身份，保留所有真实出战和旧 deck 查询能力，迁移后确定性重放并完成本轮赛事轮询。

## 已确认决策

1. 使用稳定 `appearance_id`，不扩展现有 rank 复合主键。
2. EN 旧 deck ID 保留别名映射，旧 `get_deck(old_id)` 可用；不保留新旧重复实体。
3. 先用本地 raw 验证，再恢复 `monitor tourneys` 断点续传，不把 3710 第 1 页 64/108 队称为整场收齐。

## 1. 出战身份

`deck_appearances` 新增：

- `appearance_id`：公开稳定 ID，由 tournament_id + appearance_key 确定性哈希生成。
- `appearance_key`：内部源侧出战键，数据库约束 `(tournament_id,appearance_key)` 唯一。
- 原 deck_id/tournament_id/rank/player_ref/points/record 等字段保留；rank=-1 原样保留。

键材料：

| 通道 | appearance_key |
|---|---|
| mik | 排序后的全队 players.pinCode + 当前 deckId；无 pinCode 时保留可审计的降级并告警 |
| Limitless API | tournament + player；同 key 冲突事实报错 |
| Limitless site | player + decklist_id |
| JP | 官方 deck_code |

mik 的 teamName 不作主身份，队员数组顺序不影响键；完整队员集合不进入 SDK。完全相同重复行映射同一 ID；同 key 出现不同 rank/record 等冲突事实时中止该赛事，不后写覆盖。

`v_stat_deck_cards` 携带 appearance_id；WUR、WR-A/B、WWS、drilldown 以其连接/分组，防止同 deck/tournament/rank 的统计坍缩。`v_pairing_players` 仍按 tournament+player_ref 关联，多重 appearance 整侧剔除。AppearanceRecord 与 SDK DeckAppearance 增加 appearance_id；旧 dist 缺字段时可空兼容，appearance_key/teamName/player_ref 不新增到 SDK。

## 2. EN 内容身份与旧实体合并

EN 两通道共用规范化：

1. 抽取 `(name,set,number,count)`，number 统一字符串，空 set/number 统一 NULL。
2. 按 `(name,set,number)` 聚合 count，再排序 canonical JSON + SHA-256。
3. 保留各自源前缀；不把 archetype、section、数组顺序、decklist_id、CN card_id、env 或 fetched_at 纳入身份。

JP 同形补齐重复同卡 count 聚合；mik 源 deckId 已是内容实体 ID，不改名。

按当前 raw 预估，API decks 40,678→31,408，site 1,095 不变，减少 9,270 个重复实体。多旧 ID 合并时：

- appearances 按稳定出战身份全量重挂接，同一源出战去重，不同选手/队伍不合并。
- deck_cards 复制同一内容单份，绝不相加；不一致时从 raw 重建。
- archetype/deck_code 等 metadata 由最早出战代表确定，同日按 tournament_id/appearance_id 决胜。
- misses 重挂接，first_seen_at 取最早；resolved 与迁移后实际 card 映射一致，冲突经 remap 重建，不任取旧 resolved_card_id。

## 3. 旧 ID 别名与版本

内部保存 old_deck_id→new_deck_id 别名及 FK；导出 `decks.jsonl` 的每个 DeckRecord 增加 `legacy_ids` 数组。DB/JSONL `get_deck` 均先查新 ID，再解析别名；其他查询只返回 canonical deck，不制造统计重复。

schema_version 升 3.0.0，user_version 升 14；CHANGELOG 先预告旧 EN ID 退役为别名，再记录实施。旧 dist 缺 appearance_id/legacy_ids 时按空/None 兼容读取。

## 4. 共享 deck 环境

ingest 与 remap 共用最早非 NULL 出战日期裁决：当前赛事与 DB 已有出战一起取最早日期，后抓到的更早赛事会触发重映射，较晚赛事不覆盖。完全无日期时 env_marks=NULL 不猜。EN 两通道与 JP 一致执行；mik 卡 ID 不需要 env 映射，保留交叉校验。

## 5. migration 014 与故障安全

纯 SQL 无法重算 raw 内容哈希，因此 migration 014 由结构 SQL + 可测试的 raw 驱动数据迁移组成，在同一个 SQLite 事务中完成，全部成功后才置 user_version=14。

预检：

- 所有现存 EN deck 都有唯一 raw 映射；digest 不对应多个规范内容。
- 合并组 deck_cards 一致，或有确定的 raw 重建路径。
- appearance 合并冲突可解释；任何同 key 不同事实拒收。
- 别名、appearances、deck_cards、misses 的挂接目标完整。

异常时回滚 user_version 13、临时对象与全部数据变更；不得半迁移后仍标 14。

## 6. 测试与真实验收

自动化：EN 条目正逆序/重复表示同 ID、count 变化不同 ID；3710 两队一 deck 两 appearance；teamName/队员顺序不改 ID；同 key 冲突报错；fan-in 不丢出战、不重复卡表；别名双后端；跨 env 正逆序与 remap 一致；迁移故障回滚；五类统计同 rank 两出战不坍缩；旧 dist 兼容。

真实库先备份，记录各 source 的 decks/appearances/deck_cards/misses/full/partial、pairings 和 tournaments。迁移后核对 EN 合并规模、旧实体无重复、别名可解析、孤儿/FK/integrity、full 不降级。

3710 本地第 1 页先验收 64/108 队、两队 `688431` 均有独立 appearance；第二次重放逐行幂等。然后恢复 `monitor tourneys`，有第 2 页则收齐，源侧异常明确留痕。最后重放本地 ingest、重导 dist，验证 schema 3.0.0 / user_version 14、manifest=实时 SQL、DB/JSONL 契约一致。

## 非目标

- 不伪造名次、不合并丢队、不跳过冲突。
- 不改变 pairings 选手关联语义，不把队伍 key 写入 player_ref。
- 不跨 EN 源前缀合并，不因提高 full 率猜映射。
