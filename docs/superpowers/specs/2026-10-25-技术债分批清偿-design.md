## 1. 背景与目标

当前 M0–M12 已完成，1178 项测试与 ruff 全绿，但完整评估确认以下缺口仍存在：

- FR-4 的 `search/get` 仍为桩；验收器在缺快照时可假绿，A1/A3 覆盖不足。
- 迁移与导出失败路径缺少原子性，schema major 尚未按 FR-6.2 补升。
- EN 内容身份与共享 deck 环境口径存在潜在顺序依赖。
- 采集限流、raw 写入、统计/SDK、mapping/validate/monitor 有若干 P2 健壮性与契约缺口。
- 3 套 JP 卡组需实库重放自愈，Brave Bangle、CBB、isQual 需外部事实核销。

目标是在不扩大产品范围的前提下，按风险与依赖分 7 个任务全部清偿可执行项；每项都有可复现的验收证据和独立提交。

## 2. 已确认决策

1. 本轮覆盖分批全部清偿，不仅限于第一批核心。
2. 任务粒度采用 7 个风险批次，不做 3 个混杂大批次，也不逐缺陷拆成数十个任务。
3. `effect_tags` list→dict 的破坏性语义变更补升 `schema_version=2.0.0`，不采用 PRD 豁免。
4. 每个任务先写任务文档，按 `tasks/README.md` 完成、归档并同步 STATUS/CHANGELOG；语义变化先改 PRD。
5. 当前嗨皮组合 L0 与赛事轮询属于独立 ops 工作，先单独收尾，不混入 task 059–065 的任何提交。
6. 实施使用隔离工作区；真实库操作先备份，外部核查遵守既有采集红线。
7. 不因清零技术债而实施 PRD 已排除或明确后置的功能。

## 3. 任务分解

### task 059：查询 CLI 与验收可信度

**目标**：补齐 PRD 已承诺的查询入口，并让验收在关键前置缺失时可靠失败。

范围：

- `ptcgdb search` / `ptcgdb get` 复用 SDK 查询能力，明确输出、分页、未命中和退出码契约，补 CLI 测试。
- A1/A4/A8 缺必需快照改为 FAIL；A1 同时覆盖白名单逐卡核对与现有系列对账，不降低 PRD 覆盖完整口径。
- A3 owner 校验改读 `config/vocabularies/owners.yml`，新增 owner 不再需要改代码。
- A7 异常记 FAIL 且不阻断 A8；同步十四件套文案。

验收：正常路径与 SDK 一致；空库/缺快照不假绿；系列对账失败可被 accept 检出；新增 owner 负向用例有效；A7 失败后 A8 仍执行。

### task 060：迁移、导出与 schema 2.0

**目标**：保证结构升级和重复导出在失败时不留下半新半旧状态，并补齐结构版本契约。

范围：

- 迁移脚本事务化，覆盖破坏性迁移中途异常后的回滚、无临时对象残留和安全重跑。
- 导出在临时目录完整构建后替换；失败时既有 dist 逐字节保持不变。
- 修复同目录 parquet→`--no-parquet` 的旧文件和 checksum 登记；补 parquet 与 cards.jsonl 行数一致性断言。
- `SCHEMA_VERSION` 升 2.0.0；既有库 meta 可升级，不被 `INSERT OR IGNORE` 固定为旧值。
- DB SDK、JsonlBackend、manifest、legality.json 同步；CHANGELOG 记录补升原因，PRD FR-6.1/FR-6.2 记录 2.0.0 及迁移、导出失败原子性语义。

验收：故障注入下 DB 与 dist 均可恢复；旧 dist 连续导出无陈旧件；新旧库 schema_version 均为 2.0.0，旧 list effect_tags 输入兼容测试仍过。

### task 061：实库自愈与外部事实核销

**目标**：清偿已经存在的实库异常，并把外部数据疑点变成明确结论，而不是猜测性代码。

范围：

- 备份后用既有本地 raw 重跑 `ingest-jp`，验证 JP 229/229 套卡组合计 60，其他赛事数据不漂移、full 不降级。
- Brave Bangle 先修正“2024 年卡”的留痕：本地 EN 证据为 White Flare/WHT 80、2025-07-18、I 标。再按既有小样本官方核对红线确认是否存在简中印刷；无印刷则关闭，存在才补源桥并 remap。
- CBB 核查 mik 原始列示、同号异画与人工卡面锚；事实不足保持只显分子，不放宽 sanity 门。
- isQual 用独立前端或官方样本核实含义；证据不足继续保真透传，不按名称翻转。
- 每项形成报告，区分已修复、已关闭和外部阻塞。

验收：JP 异常归零且复跑幂等；其余三项均有证据链和明确结论/阻塞原因，不新增无依据映射或统计口径。

### task 062：赛事内容身份统一

**目标**：同一卡组内容与同一共享实体在重抓、重排、跨环境重放后仍保持稳定身份和映射。

范围：

- EN 两通道 deck_id 采用顺序无关的规范化内容哈希，重复条目 count 不丢失。
- 设计旧 deck_id 迁移/合并：保留 appearances 引用与去重语义，避免新旧哈希并存制造第二批实体。
- 统一 ingest 与 remap 的共享 deck env 裁决为最早出战赛事环境，EN 两通道与 JP 一致执行；无出战日期的实体保持 NULL，不猜。
- 正序/逆序 ingest、跨 env 出战、remap 后结果一致，既有 full 不降级。

验收：任意条目重排不改变 deck_id；旧实体迁移后 appearances 不丢失、不重复；跨环境重放确定且幂等。涉及身份语义变化先改 PRD。

### task 063：采集与 raw 层韧性

**目标**：在“绝不硬闯”红线下，提高限流、瞬断和写盘中断时的可恢复性。

范围：

- HTTP 429 统一有限退避与最终 aborted/question 语义；403/验证码不自动闯。
- 长任务少量连续失败可冷却恢复，持续失败仍熔断；不采用无限重试或单纯放大阈值。
- raw 原子写，故障时只暴露旧完整文件或新完整文件，兼容 Windows rename。
- swiss 同秒不同内容不丢快照，fetched/unchanged 与实际写入一致。
- 根 logger 改模块 logger；独立 Limitless 清单页复用 24h TTL，monitor 既有强制刷新行为不变，内容不可变详情不受影响。

验收：mock 覆盖 429 JSON/HTML、瞬断恢复、持续失败熔断、写盘中断和同秒快照；三清单与断点续传完整，无需真实触发源站风控。

### task 064：统计、合法性与 SDK 契约

**目标**：消除参数、分页和双后端分叉，并改善大 dist 的统计加载与诊断。

范围：

- 校验 `usage_basis`、matchup granularity、`query --limit`、search/list_decks 的 limit/offset；固定 0 与负数语义。
- B 层 mirror 与空结果 q0 meta 契约；Windows GBK 子进程中文 JSON 输出。
- 孤儿 appearance 时双后端一致；JSONL 流式加载、必要索引和统一带文件名的错误诊断。
- caliber 文本行尾归一；rollback 同日 `.9/.10` 正确选择。
- deprecated 不参与同名组规则推导；显式放入卡组仍由合法性层拒绝。
- 勘误 resolved/latest card_id 登记口径文档化；ErrataSeed 拒绝纯空白。

验收：双后端正常与异常输入契约一致；大 dist 结果不变并有内存/耗时基线；空结果 meta 稳定；非法输入得到统一错误而非 traceback 或静默降级。

### task 065：归一、映射、校验与运维收尾

**目标**：清理剩余可执行 P2、测试盲区与过期文档，不引入新功能。

范围：

- EN/JP 映射候选排除 deprecated；fill_en/fill_ja/fill_tera 统一 active/草稿口径。
- 日期底线跳过保留可审计 tournament_id 清单；fill_ja 同值不计 filled。
- 句级括号块使用 Unicode 空白判定；dispose 异常路径用 spy 断言并覆盖新入口。
- 通知模板单次渲染，桌面命令非零不进入 sent；通知失败仍不阻断主管线。
- CLI 非法日期友好退 2；只读命令缺库不创建文件；dry-run help 准确描述 products 刷新。
- reconciliation 缺目录守卫与 deprecated 文档；legacy effect_tags 兼容语义说明。
- 清理 Swiss、tera、derive、ambiguous、七件套等旧注释；处理 datetime adapter 弃用警告。

验收：各项负向用例通过，既有正常数据零漂移；新增 owner/词表/新机制仍走开放配置；文档与当前拍板一致。

## 4. 共同工程与验证约定

1. **任务循环**：每个任务先建 `tasks/NNN-*.md`，同一时刻原则上一个 DOING；完成后归档 `tasks/done/` 并同步 STATUS/CHANGELOG。
2. **PRD 先行**：deck_id/env、验收口径、schema 或其他语义变化先修改 PRD；纯缺陷修复不借机改规则。
3. **TDD**：先写能复现问题的失败测试，再做单点修复；不顺手重构无关模块。
4. **验证**：每任务先跑定向测试，再跑全量 `pytest -q` 与 `ruff check .`；涉及双后端时跑真实 dist 契约冒烟。
5. **真实数据**：凡迁移、ingest、deck 合并或实库自愈，先备份并记录前后计数、孤儿/重复实体、full/partial 和 FK/integrity。
6. **提交**：每个任务独立 `task(NNN): ...` 提交，包含代码、测试、任务文档和状态记录；不混入其他任务、ops 数据或 `.scratch` 文件。
7. **外部事实**：网络仅用于 task 061 明确需要的核查，遵守既有频率、请求量和官方站红线；无法核实即记录阻塞。
8. **范围控制**：Swiss 入库、效果 DSL、FR-10 sim 细表、evolution_chain 违规、繁中填充、跨语言 archetype 归一、matchup full 过滤、JP 无人数 B 层统计、历史 effective_text 改口径均不在本轮。
