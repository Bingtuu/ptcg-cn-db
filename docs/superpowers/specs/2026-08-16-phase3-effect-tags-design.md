## 定位与边界

Phase 3 在本项目的口径 = **效果粗粒度标签层**，交付物 `effect_tags`。不做效果 DSL、不做规则引擎——规则引擎属下游另立项目（PRD 非目标，TCG ONE 先例）。标签层是两个项目之间的数据接缝：规则引擎经导出契约/SDK 消费 `effect_tags` + `text_raw` + 结构化 attacks。

**范围收口（用户拍板③）**：词表设计、命中率验收、人工抽检一律以**简中当前环境卡池（F 之后现存机制，standard GHI 口径）**为准；open 赛制历史卡的旧机制（GX/棱镜之星/TAG TEAM 等已退场机制）只做整理性打标，不追全量覆盖，残留如实入 question 不阻塞验收。

**扩展性（用户拍板④）**：新规则/新特性/新标签出现 = **词表配置追加，零代码改动**（沿用项目"枚举一律开放字符串 + 词表文件"硬规矩）。9/16 30周年庆典新机制是第一个实战检验点。

## 数据结构设计

`cards.effect_tags`（已预留，JSON NULL）填充为：

```json
{
  "tags": ["draw", "search"],
  "detail": {
    "attacks": {"0": ["spread"]},
    "ability": ["protection"],
    "text": ["draw", "search"],
    "flags": ["once_per_turn"]
  }
}
```

- `tags`：卡级去重标签集——检索/筛选/统计消费面。
- `detail`：分项明细（招式按下标、特性、卡面文本三段）+ `flags`（机制 flag：coin_flip / once_per_turn / conditional）——规则引擎精确定位消费面。
- 无标签卡（纯伤害招式、基本能量等）= `{"tags": [], "detail": {}}` 而非 NULL？→ **否**：维持 NULL = 未标注 / 空对象 = 已标注无命中，语义区分留给 038 实测后定（默认空对象，NULL 仅历史遗留）。

## 标签词表 v2（20 意图标签 + 3 机制 flag，经 2026-08-16 全库文本实证 review）

**Review 方法**：抽出当前环境（G/H/I）全部 distinct 训练家卡文本 250 条逐条核对 + 特性文本 868 条（280 distinct）聚类核对。结论：**初版草案不完整**——实证发现 5 个遗漏类别（增伤 / 面板与规则修正 / 无效化与禁止 / 奖赏卡操控 / 牌库削减），2 个定义错误（检索未含"直接放备战区"；回合限次的真实措辞是「每次在自己的回合有1次机会」而非"一回合一次"）。**多标签是常态而非例外**：多数训练家卡与特性承载 2 个以上意图（如 换位+能量转移 / 拆能+填能 / 填能+抽牌），标签集合设计（非单选）是硬性正确选择。

**意图标签 20 个**（按对战意图分类，词表上限沿用 PRD §6.4 ≤20）：

| 类 | 标签 | 含义与实证来源 |
|---|---|---|
| 牌库资源 | `draw` | 抽牌（含"补至 N 张"、双方重抽） |
| | `search` | 检索牌库找卡——**含入手牌与直接放备战区/直接进化登场**（巢穴球类；初版定义漏了进场向） |
| | `mill` | 牌库削减——自己牌库卡放于弃牌区（自堆，迷失轴引擎；**v2 新增**） |
| | `discard_recover` | 弃牌区回收（回手牌/回牌库；能量从弃牌区**附着**归 energy_accel） |
| 手牌博弈 | `hand_disrupt` | 手牌博弈：查看/公开/丢弃/洗回（含双方洗抽，奇树类；初版 hand_reveal 并入） |
| 伤害与生存 | `damage_boost` | 增伤——"伤害「+30」"类（讲究腰带头带类高频，**v2 新增**，初版重大遗漏） |
| | `spread` | 铺伤/放置伤害指示物 |
| | `heal` | 回复 HP，**含特殊状态恢复** |
| | `protection` | 防御向修正：减伤/免伤/效果免疫/特殊状态免疫/弱点抗性消除 |
| 状态 | `status` | 赋予特殊状态（中毒/灼伤/麻痹/睡眠/混乱） |
| 能量线 | `energy_accel` | 能量加速——额外附着（来源不限：牌库/弃牌区/手牌） |
| | `energy_move` | 能量转移——场上宝可梦间转附（不增量；**v2 新增**） |
| | `energy_disrupt` | 能量干扰——拆/回对手能量 |
| 场面控制 | `gust` | 强制对手换位（老大的指令类） |
| | `switch` | 己方换位 |
| | `bounce` | 己方宝可梦回手/回库 |
| 无效化 | `lock` | 无效化与禁止——特性/道具消除、无法使用招式、无法撤退、不受弃牌效果（**v2 新增**，与 protection 的界线：protect 己方，lock 消除机制） |
| 修正 | `modifier` | 面板与规则数值修正——最大 HP± / 撤退费± / 招式能耗± / 奖赏卡拿取增减 / 备战区容量（**v2 新增**，实证聚成一簇连续修正类；奖赏卡操控并入，不再单列） |
| 进化 | `evolution` | 进化支援——直接进化/跳阶段/退化（退化对手 = 干扰向，同标签 note 注明） |
| 特殊行为 | `special_behavior` | 谜之化石类"训练家卡当宝可梦"、招式学习器 body 等（PRD §6.4 点名，人工名单驱动） |

**机制 flag 3 个**（不计入 ≤20 上限，落 `detail.flags`，是触发/约束标记而非意图）：

- `coin_flip`：含硬币随机（AI 模拟 RNG 建模用）
- `once_per_turn`：回合限次（真实措辞「每次在自己的回合有1次机会」「可以使用1次」）
- `conditional`：含条件触发（奖赏卡张数比较/昏厥触发/先后攻限制等）——只标记"此卡含条件"，**不解析条件内容**（条件结构化 = 规则引擎职责）

**明确不做**（review 中识别并排除）：①条件触发的内容解析（归入 flag 即止）；②旧机制（GX/棱镜/TAG TEAM 等 F 前退场机制）全量覆盖——按范围收口拍板从简，残留入 question；③招式固定伤害与 cost——已由 attacks 子结构承载，不重复打标。

词表文件 `config/vocabularies/effect_tags.yml`：每标签 = 中文名 + `patterns`（正则/关键词列表，新旧措辞并列——气绝/昏厥同义层在此解决，代码不做术语规范化）+ `note` + 可选 `scope`（pokemon/trainer/energy 限定）；开放追加。

## 标注器架构

`ptcgdb/mapping/effect_tags.py`，照 `map-tera` / `map-ja-trainer` 先例：

- **纯函数核** `tag_card(card) -> EffectTags`：分项（attacks[i].effect_text / ability 文本 / text_raw）各跑词表模式 → 卡级聚合去重。
- **确定性 + 幂等 + 可整体重跑**：同输入同输出，复跑零漂移；规则与数据分离（模式全在词表 yml，代码零内置词）。
- **不猜原则**：模式冲突 / 疑似新机制未覆盖 → 进 question 清单（归类报告），不写半个标签。
- **新旧用词同义层**：气绝/昏厥等朱紫前后措辞差异在词表 patterns 内并列，代码不做术语规范化（text_raw 红线不变）。
