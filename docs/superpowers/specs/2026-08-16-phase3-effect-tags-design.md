## 定位与边界

Phase 3 在本项目的口径 = **效果粗粒度标签层**，交付物 `effect_tags`。不做效果 DSL、不做规则引擎——规则引擎属下游另立项目（PRD 非目标，TCG ONE 先例）。标签层是两个项目之间的数据接缝：规则引擎经导出契约/SDK 消费 `effect_tags` + `text_raw` + 结构化 attacks。

**范围收口（用户拍板③）**：词表设计、命中率验收、人工抽检一律以**简中当前环境卡池（F 之后现存机制，standard GHI 口径）**为准；open 赛制历史卡的旧机制（GX/棱镜之星/TAG TEAM 等已退场机制）只做整理性打标，不追全量覆盖，残留如实入 question 不阻塞验收。

**扩展性（用户拍板④）**：新规则/新特性/新标签出现 = **词表配置追加，零代码改动**（沿用项目"枚举一律开放字符串 + 词表文件"硬规矩）。9/16 30周年庆典新机制是第一个实战检验点。

## 数据结构设计

`cards.effect_tags`（已预留，JSON NULL）填充为：

```json
{
  "tags": ["draw", "search"],
  "detail": {
    "attacks": {"0": ["spread"]},
    "ability": ["protection"],
    "text": ["draw", "search"]
  }
}
```

- `tags`：卡级去重标签集——检索/筛选/统计消费面。
- `detail`：分项明细（招式按下标、特性、卡面文本三段）——规则引擎精确定位消费面。
- 无标签卡（纯伤害招式、基本能量等）= `{"tags": [], "detail": {}}` 而非 NULL？→ **否**：维持 NULL = 未标注 / 空对象 = 已标注无命中，语义区分留给 038 实测后定（默认空对象，NULL 仅历史遗留）。

## 标注器架构

`ptcgdb/mapping/effect_tags.py`，照 `map-tera` / `map-ja-trainer` 先例：

- **纯函数核** `tag_card(card) -> EffectTags`：分项（attacks[i].effect_text / ability 文本 / text_raw）各跑词表模式 → 卡级聚合去重。
- **确定性 + 幂等 + 可整体重跑**：同输入同输出，复跑零漂移；规则与数据分离（模式全在词表 yml，代码零内置词）。
- **不猜原则**：模式冲突 / 疑似新机制未覆盖 → 进 question 清单（归类报告），不写半个标签。
- **新旧用词同义层**：气绝/昏厥等朱紫前后措辞差异在词表 patterns 内并列，代码不做术语规范化（text_raw 红线不变）。

## 落库与管线

- 写入走独立 CLI `ptcgdb tag-effects [--set X] [--dry-run]`，**不侵入 ingest 主流程**（039）。
- L0 钩子（新卡入库自动打标）放 040，随抽检核销后接入。
- 导出契约：`cards.jsonl` / DB 导出加 `effect_tags` 字段（只加不删）；SDK `Card` 模型补字段；schema.md 同步。

## 验收

- 词表 v1 经用户拍板（038 命中率报告驱动）。
- 全库首标：每标签命中数落报告；当前环境卡池零命中卡全归类（无标签合理 / 词表缺口），**零"不知道是什么"项**（039）。
- 人工抽检 ~100 张（用户在场，A2/A3 同款流程），一致率与误标分类落报告（040）。
- 扩展性验证：模拟新增一个标签 = 仅改词表 yml，复跑生效（040 测试锚定）。
- 测试全绿 + ruff 全净；PRD §6.4 展开同步。
