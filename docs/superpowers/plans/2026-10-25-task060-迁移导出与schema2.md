# 迁移、导出与 schema 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让每个结构迁移和每次 dist 导出在异常时保持旧状态可恢复，并将数据库及全部导出后端的结构版本统一升级为 2.0.0。

**Architecture:** 迁移执行器把 SQL、`user_version` 和异常回滚纳入同一 SQLite 事务。导出器在目标目录旁构建临时目录，完整校验后通过目录替换发布，失败时删除临时目录并保留旧 dist；schema 版本仍由 `migrations.SCHEMA_VERSION` 单点提供。

**Tech Stack:** Python 3.14、sqlite3、SQLAlchemy 2、Pydantic v2、pyarrow、pytest、ruff。

- [ ] **Step 3: 实现单迁移事务和 meta 更新**

把 `SCHEMA_VERSION` 改为 `2.0.0`；每个脚本按以下结构执行，异常先 rollback 再抛出，成功后进入下一版本：

```python
script = path.read_text(encoding="utf-8")
try:
    conn.executescript(
        "BEGIN IMMEDIATE;\n" + script
        + f"\nPRAGMA user_version = {version};\nCOMMIT;"
    )
except Exception:
    conn.rollback()
    raise
```

全部迁移结束后使用幂等 upsert，而非 `INSERT OR IGNORE`：

```sql
INSERT INTO meta (key, value) VALUES ('schema_version', ?)
ON CONFLICT(key) DO UPDATE SET value=excluded.value
```

- [ ] **Step 3: 实现临时构建与替换**

保留现有导出主体为 `_export_all_to_dir(db_path, staging, parquet=parquet)`；新 `export_all` 只负责发布：

```python
out_dir.parent.mkdir(parents=True, exist_ok=True)
staging = Path(tempfile.mkdtemp(prefix=f".{out_dir.name}.tmp-", dir=out_dir.parent))
backup = out_dir.with_name(f".{out_dir.name}.old-{uuid.uuid4().hex}")
try:
    manifest = _export_all_to_dir(db_path, staging, parquet=parquet)
    existed = out_dir.exists()
    if existed:
        os.replace(out_dir, backup)
    try:
        os.replace(staging, out_dir)
    except Exception:
        if existed:
            os.replace(backup, out_dir)
        raise
    if existed:
        shutil.rmtree(backup)
    return manifest
finally:
    if staging.exists():
        shutil.rmtree(staging)
```
