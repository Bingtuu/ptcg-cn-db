## 目标
SDK 双后端补赛事卡组查询：现状 decks/deck_cards 等四表无 SDK 方法，下游只能裸 SQL。新增 `get_deck(deck_id)` / `list_decks(archetype, date_from, date_to, mapping_status="full")` 返回 frozen 模型，并把「统计只消费 full」口径封装进 API 默认值。顺带清偿性能：`legal_at`/`effective_text` 每次全量物化 12,420 张卡（实测 0.94s/0.80s），加后端实例级缓存（改实现不改接口）。
