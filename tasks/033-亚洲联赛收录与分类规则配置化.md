## 设计

### A. 分类规则配置化（`config/site_tournament_rules.yml`，新）

单一事实源，合并现在分离的 SITE_TIER_PATTERNS / SITE_CUT_LIMITS / JP_DOMESTIC_PATTERN 三个代码常量：

```yaml
min_players: 32
tiers:                  # 收侧：tier 正则与名次截断合一，消除「新 tier 忘配 cut」的坑
  - tier: worlds
    patterns: ["World Championships"]
    cut_limit: 32
  - tier: international
    patterns: [...]     # NAIC/EUIC/LAIC/OCIC 原样迁入
    cut_limit: 32
  - tier: master_ball_league
    patterns: ["Master Ball League"]
    cut_limit: 32
  - tier: korean_league
    patterns: ["Korean League"]
    cut_limit: 32
  - tier: premier_ball_league
    patterns: ["Premier Ball League"]
    cut_limit: 8        # 对标 league_cup 档
  # special / regional / league_cup 原样迁入
reject:                 # 拒侧：明细化理由，只留真 JP 卡赛事
  - pattern: "Japan Championships|Champions League|JCS"
    reason: "JP 卡国内赛，EN 桥走不通，JP 对齐二期再议"
```

- 判定顺序不变：人数门 → 收侧按序 → 拒侧按序 → 兜底拒（「未命中官方系列赛名称正则」）。
- 加载时校验：每档必须有 patterns+cut_limit；正则编译检查；tier 名必须在 tournament_tiers.yml 词表内。校验失败 fail-fast。
- Korean/Premier Ball League 从拒侧挪收侧；拒侧保留 Japan Championships/Champions League/JCS。

### B. 词表三词条（`config/vocabularies/tournament_tiers.yml`）
