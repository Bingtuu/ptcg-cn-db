## 目标
SDK 双后端补赛事卡组查询：现状 decks/deck_cards 等四表无 SDK 方法，下游只能裸 SQL。新增 `get_deck(deck_id)` / `list_decks(archetype, date_from, date_to, mapping_status="full")` 返回 frozen 模型，并把「统计只消费 full」口径封装进 API 默认值。顺带清偿性能：`legal_at`/`effective_text` 每次全量物化 12,420 张卡（实测 0.94s/0.80s），加后端实例级缓存（改实现不改接口）。

**task 045 SDK 卡组查询接口 + legal_at 缓存 ✅（2026-08-28，PRD v1.29，user_version=13 无迁移）**

- **SDK 接口**：ABC `CardDatabase` 追加 `get_deck(deck_id)` / `list_decks(*, archetype, date_from, date_to, mapping_status="full", limit, offset)` 两个 abstractmethod + frozen 模型 `Deck`（内容实体 + `cards: list[DeckCardRecord]` + `appearances: list[DeckAppearance]`，tournament_date 联 tournaments 冗余；player_ref 不出 SDK，隐私最小化延续 FR-9.5）。口径：默认只回 full（封装统计口径 FR-9.1，None 放开）；窗口 = 存在出战条目其赛事日期 ∈ 闭区间（日期 NULL 不进窗口）；deck_id 升序稳定分页；未映射 card_id=NULL 条目不丢不猜 raw_name 保真（FR-9.2）。
- **双后端**：DbBackend SQL 直查四表；JsonlBackend 懒加载既有四件 JSONL（导出契约零变更，dist 旧导出直接可读）。排序确定化（cards 按 raw_name、appearances 按 tournament_id+rank），group_key 冗余列对齐 exporter 口径。
- **缓存**：DbBackend 实例级 `_cache`（cards/groups/snapshots/errata 一次加载 + legal_at 按 (format,date) 缓存 frozen LegalityPool）；JsonlBackend `_pool_cache` 同理。接口签名零变化；失效语义 = 实例为只读快照，L0 增量后重开后端。
- **实库冒烟**：`list_decks(archetype='沙奈朵')` 158 == 裸 SQL 158；get_deck 抽样（mik_moe 29 行 60 张）逐字段对 SQL 一致；窗口 2026-07 full 681 == SQL 681；mapping_status=None 2,720 == decks 总数；legal_at 1.216s → 缓存命中 0.0000s；dist/ 旧导出 JSONL 双后端契约 4 组参数 + get_deck 全等。
