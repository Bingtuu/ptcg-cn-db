## 目标
索引类 raw（产品清单/系列详情/赛事 series-list/赛事 list）是可变列表，"存在且 hash 有效即跳过"的断点续传口径会让新系列/新赛事永久不可见。给索引页加 TTL 自动刷新（卡详情等内容不可变文件维持原口径），并用 CBB6C + 30thP 增量收编做实战验证。

## 已核实前提（2026-09-13）
- L0（monitor/l0.py:164）已 force 刷新 products.json——task 054 任务档「L0 探测链路依赖此文件刷新节奏」注记有误，本任务一并订正；真正缺口在**手动 scrape 链路**与**赛事 runner 索引页**。
- `scrape sets` 现状浪费：无条件实抓 product-list 但 write_raw 非 force 跳过 → 新数据抓到却落不了盘（30thC/MP/CBB6C 缺席的根因）。
- 30thP cardsNum 18→27：系列详情（set cards.json）同样是可变索引。
- 卡详情（card detail / tournament detail / rank / deck-static / deck detail）内容不可变或另有补抓通道（backfill-topcut --fetch），维持"有效即跳过"。

## 设计
- `raw_store` 新增 `is_fresh_raw(path, max_age)`：hash 有效且 `fetched_at` 在 TTL 内。
- 默认 TTL = 24h（模块常量，runner 构造参数可覆盖）；force=True 照旧全量重抓。
- 接入点：`ScrapeRunner.scrape_sets`（products.json 新鲜则读缓存，陈旧才实抓+落盘；系列详情 cards.json 同口径）/ `ensure_products` / `_scrape_set_cards` 详情补抓 / `TournamentScrapeRunner` 的 series-list 与 tournament list 翻页。
- 不加 CLI 旗标（TTL 自动生效零纪律成本）；文档落 data-sources.md §1。
