## 目标

在「绝不硬闯」红线下，提高限流、瞬断和写盘中断时的可恢复性：HTTP 429 统一有限退避、瞬断冷却恢复、raw 原子写、swiss 同秒快照不丢、logger 归位、清单页 TTL 复用。并补上 2026-11-04 运维教训：ingest-tourneys 直连 CLI 缺收集底线守卫（STATUS 结构性条目）。

## 现状与输入

- 2026-10-22 采集瞬断曾触发连续 5 次失败熔断，探源为瞬时网络问题——需要少量连续失败可冷却恢复，持续失败仍熔断。
- 2026-11-04 `ingest-tourneys` 直连 CLI 不带 `--date-from` 时无底线守卫，误将全量历史 mik raw（2,880 场退赛前赛事）入库，从备份还原收口——结构性守卫补进本任务。
- 根 logger 直用、Limitless 清单页 TTL 不复用，属第二轮 review P2 残留。

## 步骤

- [x] HTTP 客户端：429 统一有限退避（JSON/HTML 两种响应面），最终失败语义 RateLimitedError（TransientHttpError 子类，runners 记 question/aborted）；403/验证码不自动闯
- [x] 长任务瞬断冷却恢复（CIRCUIT_COOLDOWN=60s 半开探测：成功闭合、失败立即重开），不无限重试、不放大阈值
- [x] raw 层原子写：同目录临时文件 + os.replace（Windows 兼容），故障只暴露旧完整文件或新完整文件，无临时残留
- [x] swiss 同秒不同内容不丢快照（unique_swiss_snapshot_path 追加 -2/-3 序号）；fetched/unchanged 按 write_raw 实际返回值记账
- [x] 根 logger 改模块 logger（ptcgdb.scrapers.runner）；Limitless 清单页复用 24h TTL（过期重抓覆盖、期内零请求、force 恒重抓），详情页"有效即跳过"不变，monitor 强制刷新行为不变
- [x] ingest-tourneys CLI 直连路径补收集底线守卫：无 --date-from 时拒绝入库（退 2），显式 --allow-full-history 可全量重放；monitor 编排路径自动注入 cn_collection_start() 不受影响
- [x] mock 测试覆盖：429 JSON/HTML、瞬断恢复、持续失败熔断、写盘中断、同秒快照、TTL 复用、CLI 底线守卫（tests/test_scrape_resilience.py，16 项）
