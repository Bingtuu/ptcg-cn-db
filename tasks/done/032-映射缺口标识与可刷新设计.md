## 设计

核心性质：**映射判定的是「卡身份」而非「环境合法性」，卡池增长只让 partial → full 单调升级，永不降级**。半年后简中 Mega 包入库（L0，name_en 英文桥 mik raw 自带）→ remap 命中历史 Mega 卡 → partial 自动升 full；赛事 env 列保持历史事实不受刷新影响；SQLite 视图查询时计算，统计层免重建。

### B. misses 标识层（migration 011，user_version=11）

新表 `deck_card_misses`（不导出，对内运维表）：

| 列 | 口径 |
|---|---|
| deck_id | FK→decks |
| raw_name / raw_set / raw_number | 源侧条目保真（set/number 可缺，归一为 ''） |
| resolved_name_en | ptcd 定位出的规范英文名（ptcd_miss 时 NULL） |
| miss_kind | 开放字符串：no_cn_printing / ptcd_miss（ambiguous 预留） |
| resolved_card_id | NULL=未解；remap 命中后回写 |
| first_seen_at / resolved_at | 时间戳 |

- PK (deck_id, raw_name, raw_set, raw_number)。
- 双通道 ingest 今后每个未解析条目同步 upsert miss（已 resolved 的不动）。
- **既有数据回填 = 独立 DB 锚定 pass（backfill_misses）**：以 deck_cards.card_id IS NULL 的现存行为准，去 raw 找对应 (set,number)——site 通道扫 decks/list/*.json 重算内容哈希 deck_id；API 通道扫 standings/*.json 用 parse_standings_entry 重算 deck_id。**不重跑 ingest-limitless**（会把已清除的残留杯赛吃回来）。

### C. remap-decks 刷新层

CLI `ptcgdb remap-decks [--source ...]`：对 resolved_at IS NULL 的 miss 用当前卡池重跑 map_decklist_card（env_marks 由该 deck 最早出战赛事日期推导）；命中则回写 deck_cards（同 card_id 冲突合并 count）、miss 标 resolved、重算 mapped_ratio/mapping_status；产出前后对照。幂等。task 031 将把 remap_decks(source=None) 挂进 L0 新卡入库后钩子。
