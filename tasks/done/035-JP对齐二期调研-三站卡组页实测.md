## 目标

实测三个 JP 卡组聚合站（PokecaBook / ポケカ飯 / pokecardlab）的卡组页字段形态，用现有库做映射演练，**拿到 JP 通道的 full 率预估**，据此决定 JP 对齐二期的投入形态（全量管线 / 降级只收壳 / 暂缓）。这是 JP 对齐二期的调研前置任务——只调研、不建管线、不改 schema、不改 PRD。

## 背景与已知

- JP 对齐窗口 = 2025-01-24 ~ 2026-01-22（`config/tournament_envs.yml` JP 旋转日历段，G/H/I），历史静态数据，无时效压力。
- 最大不确定项：聚合站卡组页**是否给 set+number**。EN 通道 full 率 ~78% 靠 ptcd (set,number) 结构化定位；若 JP 站只有日文卡名，只能走 `name_ja` 桥——name_ja 覆盖 9,480/12,420（76.8%），未覆盖 2,857 张中 2,715 是 trainer（赛事卡组主力卡型）。
- players.pokemon-card.com 官方卡组码需浏览器渲染且 WAF 严格，违反 pokemon-card.com 红线（≤35 请求、≥2s/请求、只抽样核对）——**官方卡组码路线不做**；players 壳 JSON（名次+卡组码）仅用于小样本对账。
- 三站 robots 近全放行（task 028 调研），但仍沿用项目限速红线 ≥2s/请求。

## 步骤

- [ ] 三站各取样本：站点结构（索引页/卡组页 URL 形态）、卡组页字段清单（日文卡名？set+number？罕贵度？赛事名/名次/日期标注？截断口径）、更新频率与历史覆盖（是否覆盖 2025-01~2026-01 窗口内 CL/City League）、实测响应与限速迹象
- [ ] 抓取样本落 `data/raw/`（append-only，样本量每站 ≤10 页，限速 ≥2s/请求）
- [ ] 映射演练：从样本卡组提取卡标识 → 对库内 name_ja / (set,number) 草对 → 统计 full / partial / miss 率；miss 归类（name_ja 未覆盖 / 日文名形态差异 / Mega 时代卡 no_cn_printing）
- [ ] players.pokemon-card.com 壳 JSON 抽样对账（≤10 请求，核对名次与 archetype 标注可信度）
- [ ] 产出：full 率预估 + 主源选型建议（三站挑一主一对账）+ 投入建议（全量管线 / 降级 / 暂缓），报告 `reports/task035-jp-survey-YYYYMMDD.md`
- [ ] `docs/data-sources.md` §8b 补实测结论

## 验收标准

- [ ] 三站卡组页字段形态有实测记录（字段清单 + 样本 raw 落盘 + 限速实测），不是凭文档转述
- [ ] full 率预估有样本支撑（样本量、full/partial/miss 分布、miss 归类全记录）

## 完成总结（DONE 时填写）

**做了什么**：三站（pokecabook/pokekameshi/pokecardlab）卡组页实测 + 官方卡组码确认页解析验证 + 6 套真实卡组映射演练 + players 壳源复测。样本落盘 `data/raw/{pokecabook,pokekameshi,pokecardlab,pokemon-card-jp}/`，官方站请求 10 次（红线 ≤35 内，≥2s 间隔）。报告 `reports/task035-jp-survey-20260810.md`；`docs/data-sources.md` §8/§8b 已订正。

**验收结果**：四项验收标准全过——①三站字段形态实测记录（卡组内容载体均为官方卡组码/截图，无文本卡表；壳数据均可机读）；②full 率预估有样本支撑（6 套 360 卡张逐张归类：name_ja 单用 37% 命中 0/6 full；+TCGdex JA 名表 96.1% 命中，残 8 distinct 名全归类 = ACE SPEC 后缀 ×3 + TCGdex JA 集合缺口 ×5，均可修复 → 窗口期 deck 级 full 率预估 ≥90%）；③投入建议三档（甲=红线定向放宽做卡级管线[推荐前置拍板] / 乙=壳-only 降级 / 丙=暂缓）；④零 schema/PRD/库变更。

**两个推翻性发现**：①task 027「卡组内容无 JSON 端点需浏览器自动化」被推翻——confirm 页静态 HTML 内嵌完整卡表（隐藏 input + searchItemName 卡名表），纯正则可解析；②players 壳 JSON 端点已被 Cloudflare 拦截（403），官方壳对账源暂不可用，对账改聚合站两站互核。

**与预估的偏差**：预估 0.5~1 天，实际约 0.5 天（官方页可解析性比预期顺利）。

**遗留问题（待拍板/待立项）**：①红线是否对 deck confirm 端点定向放宽（甲/乙/丙三档，报告 §6）；②trainer 日文名表补强（TCGdex JA 重抓 + 挂接词表）是卡级路线前置，与红线无关可先行；③M6 name_ja trainer 缺口在本次演练中首次量化（老大的指令 38 张印刷 name_ja 全 NULL）。
