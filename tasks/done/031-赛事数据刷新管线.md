## 背景

task 028 设计段审查发现赛事数据持续更新/刷新未被合理设计，四项缺口：

1. **mapping_status 不随卡库增长重算**：新卡入库（L0 管线）后，既有 partial/unmapped 卡组的映射率不会自动重算，full 集合过期。
2. **赛事无增量入口**：L0 监控只盯新卡，`scrape tourneys` 手动分批，新赛事不会自动进库。
3. **EN 源赛后延迟**：Limitless 上位卡组通常赛后约 7 天才公开，一次采集拿不到完整 decklist，需定时重抓补齐。
4. **词表变更不触发重建**：`config/vocabularies/tournament_tiers.yml` 改动后，物化视图 v_tournament_weights 与导出 manifest.caliber 需重建复跑。

## 目标

赛事数据像新卡一样有可持续的增量维护管线：新赛事自动进库、映射率随卡库滚动重算、EN 卡组延迟公开自动补齐、词表变更可审计地触发重算。

## 设计段定稿（2026-08-09，task 032 后开工）

四项缺口 + task 032 追加的窗口守卫，共五件。全部复用既有引擎，本任务只做挂接与编排：

1. **ingest 窗口守卫（task 032 追加，最高优先）**：`ingest_limitless` / `ingest_limitless_site`
   的 `_ingest_one_tournament` 在写库前判定 `day ∈ alignment_window()`（与采集端同一
   单一事实源 `normalize/envs.py`）；窗口外 → `skipped_out_of_window` 计数跳过（不写
   tournaments/decks/pairings，不删既有行）；day 缺失 → 照入库 + warning（不猜）。
   开关 `enforce_window=True`（CLI `--enforce-window/--no-enforce-window`）。
   依据：raw 层 append-only，窗口外残留 raw 永存，ingest 必须防吃回（2026-08-08
   冒烟残留教训：3 场 SEASAC 杯被清除后重跑 ingest 会复活）。
2. **L0 remap 钩子**：`run_l0` 有 activated 时，后处理前先跑
   `remap_decks(raw_dir, db_path)`（task 032 引擎，幂等、partial→full 单调升级）；
   resolved>0 时摘要并入同一 CHANGELOG 版本块（`refresh_snapshot_overrides` 加
   `extra_items` 参数），并 emit "remap" 事件（通知复用）；留痕 =
   deck_card_misses.resolved_* + CHANGELOG。卡库未增长时 L0 不触发（与现状一致，
   手动 remap-decks 仍可用）。
3. **tier 词表变更 → `ptcgdb recaliber`**：比对 `caliber_hashes()` vs meta 现值；
   无漂移 → 报 unchanged 退 0；有漂移 → 全量重物化 `tournaments.tier_coef`
   （tier 列值不动，只按词表重映射系数；tier 未命中词表 → NULL 不猜）→
   `write_caliber_hashes` → data_version 递增 + CHANGELOG Changed 块
   （复用 legal/versions 的 `_bump_data_version`/`_append_changelog_block`）。
   视图是 SQL view 引用 tier_coef 列，无需重建；导出 manifest.caliber 随下次
   export 自动刷新。
4. **`ptcgdb monitor tourneys [--source mik|limitless|site|all] [--refresh-days N]`**：
   编排既有采集+入库命令，一站跑完：
   - mik：`TournamentScrapeRunner.scrape()`（断点续传，既有 raw 零请求）→
     `ingest_tourneys`；新赛事 = 本轮 fetched>0 的场次。
   - limitless：`scrape(date_from=today-refresh_days, force=True)`（赛后约 7 天
     decklist 延迟公开 → 近 N 天强制重抓，N 缺省 14=7+余量）→ `ingest_limitless`
     （窗口守卫开）。
   - site：同上（`LimitlessSiteScrapeRunner`，窗口近 N 天强制重抓）→
     `ingest_limitless_site`。
   - 默认 `--source all`；--dry-run 只打印计划（源/窗口/refresh_days）零请求。
   - 限速与熔断复用各采集器既有配置（mik 2s / limitless 6.5s / site 2.5s）。
5. **PRD v1.17**：FR-9.8 赛事数据刷新管线（窗口守卫口径 + L0 remap 钩子 +
   recaliber 语义 + monitor tourneys 编排），先改 PRD 再实现。
