## 目标
effect_tags 现状粒度 = 卡级 tags + 招式/特性/卡面文本段级 detail（`EffectTags.detail.attacks/ability/text`），不到句级。LLM 编写 DSL 时卡面文本整段进 prompt，粒度越粗越容易张冠李戴（规则引用句混进效果句的同类问题：吼叫尾误标 lock）。本任务把 `attacks[].effect_text` / `abilities[].effect_text` / trainer 卡面文本切到句级，每句独立挂 tags 并分类「效果句 / 规则引用句 / flavor 句」。

## 分层边界（红线）
- db 到**句子级切分 + 句级标签**为止；参数化解析（抽几张、检索什么类型）**不上移**，归下游 DSL 定义库
- text_raw 逐字保真不动：切分结果是派生层新字段，不回写原文

## 口径拍板（2026-08-28，PRD v1.32）
- **存储形态**：`EffectTagDetail` 追加 `sentences` 键（只加不删）——`{kind, attack_index, text 逐字, tags, sentence_class}`；段级既有字段口径不变，两层并存消费方可选粒度
- **规则引用句**：括号包裹整句（`[…]`/`［…］`/尾置`（…）`）= `rule_reference`，只标句类不打意图标签（根治吼叫尾类误标）
- **导出契约**：随 cards.jsonl/parquet 自动带出，schema.md 模型行同步
- **切分规则**：确定性零 NLP——句末符 `。！？` + 换行（括号深度 0 处）为边界，`（）()【】「」[]［］` 内不切
- **实库画像**（2026-08-28 实测）：15,487 段 → 1 句 9,592 / 2 句 3,233 / 3 句 2,047 / 4+ 句 615（38% 多句段，句级化有实益）；flavor 类保留占位（打标语料无实例）
